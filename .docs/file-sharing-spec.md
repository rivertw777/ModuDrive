# 파일/폴더 공유 기능 스펙

이 문서는 "공유" 기능이 어떤 규칙으로 동작하는지 정리한 문서입니다. 개발 지식이 없어도
읽을 수 있도록, 코드 용어 대신 실제 화면에서 벌어지는 상황을 기준으로 설명합니다.

먼저 공통 개념 두 가지만 짚고 시작합니다.

- **소유자**: 파일/폴더를 만든 사람. 공유 설정을 걸고, 바꾸고, 없애는 것은 **오직 소유자만**
  할 수 있습니다.
- **권한 종류**

  | 권한 | 할 수 있는 것 |
  |---|---|
  | 뷰어 | 보기, 다운로드 |
  | 편집자 | 보기, 다운로드, 이름 변경 |

---

## 1. 직접 공유와 상속 공유

공유는 두 가지 경로로 생깁니다.

- **직접 공유**: 소유자가 특정 사람(이메일)을 지정해서 이 파일/폴더 하나에 권한을 부여하는 것.
- **상속 공유**: 폴더를 공유하면, 그 폴더 안의 모든 하위 파일·폴더가 별도 설정 없이도
  자동으로 같은 권한을 물려받는 것. 하위 항목 하나하나에
  권한이 복사되어 저장되는 게 아니라, 접근할 때마다 "이 파일 위에 공유된 폴더가 있는지"를
  즉시 계산합니다. 즉 상위 폴더의 공유를 바꾸면 하위 전체에 실시간으로 반영됩니다.

### 처리 방식

- **폴더를 공유하면** → 그 폴더의 모든 하위 파일/폴더가 몇 단계 아래에 있든 동일한 권한을
  자동으로 갖습니다. 손자 폴더, 그 안의 파일까지 예외 없이 적용됩니다.
- **직접 공유와 상속 공유가 동시에 있으면** → **직접 공유가 항상 이깁니다.** 상위 폴더에서
  물려받은 권한이 더 높더라도, 이 파일에 소유자가 따로 지정해 둔 권한이 있으면 그 권한만
  적용됩니다.
  - 예시 상황:
    ```
    상위 폴더        (상속 권한: 편집자)
    └ 파일.txt       (직접 공유: 뷰어)   → 최종 권한: 뷰어

    상위 폴더        (상속 권한: 뷰어)
    └ 파일.txt       (직접 공유: 편집자) → 최종 권한: 편집자
    ```
    두 경우 모두 파일 자신에게 걸린 직접 공유가 상위 폴더의 상속 권한을 그대로 덮어씁니다.
- **직접 공유가 없고 상속만 있는 경우** → 여러 상위 폴더에서 각각 공유되어 있을 수 있는데
  (예: 조부모 폴더와 부모 폴더가 같은 사람에게 서로 다른 권한을 준 경우), 이때는
  **가장 가까운 상위 폴더의 권한**이 적용됩니다.
  - 예시 상황:
    ```
    조부모 폴더      (A씨: 편집자)
    └ 부모 폴더      (A씨: 뷰어)
      └ 파일.txt     (A씨에게 직접 공유 없음) → 최종 권한: 뷰어
    ```
    부모 폴더가 더 가까우므로 A씨는 파일에서 **뷰어**입니다 (조부모의 "편집자"가 더 높은
    권한이어도 적용되지 않습니다).
- **폴더 목록 화면(공유받은 폴더 안을 둘러볼 때)** → 폴더 자체에 걸린 권한과 그 위 조상
  폴더들의 권한 중 **가장 가까운 것**을 "이 폴더를 통해 물려받는 권한"으로 보여주고, 그
  폴더 안의 각 파일은 위 규칙과 동일하게 "그 파일 자신의 직접 공유가 있으면 그것을 우선,
  없으면 물려받는 권한"으로 표시됩니다.
- **가입하지 않은 이메일로 공유하면** → 정식 계정이 없으므로 "초대장" 상태로 보관되고,
  나중에 그 이메일로 가입하는 순간 자동으로 정식 공유로 연결됩니다. 그동안에도 메일로 받은
  링크로는 접근할 수 있지만, 2번에서 설명하듯 로그인 전에는 보기·다운로드만 되는 화면이라
  편집자로 초대받았어도 편집은 못 하고, 실제 초대받은 역할은 가입해서 로그인한 뒤부터
  적용됩니다.
- **자기 자신에게 공유하거나, 이미 공유된 사람을 다시 공유하려 하면** → 거부됩니다
  (소유자는 애초에 공유 대상이 될 필요가 없고, 중복 공유는 의미가 없기 때문).
- 소유자 자신에게는 공유 행(row)이 따로 만들어지지 않습니다.

## 2. 액세스 범위 지정

"누구에게 공유할지"를 두 가지 범위 중 하나로 정합니다.

| 범위 | 의미 |
|---|---|
| 제한됨 (기본값) | 소유자와, 소유자가 이름/이메일로 직접 초대한 사람만 접근 가능 |
| 링크 공유 | 링크(URL)를 가진 사람은 **누구나** 접근 가능 |

### 처리 방식

- **링크 공유는 항상 "뷰어" 권한만 가능합니다.** 링크는 소지한 사람이 곧 권한을 갖는
  방식이라 누가 실제로 접근했는지 특정할 수 없기 때문에, 이름을 남기는 "편집" 권한은
  링크로는 절대 내줄 수 없습니다. 편집 권한이 필요하면 반드시 1번의 "직접 공유"로
  이메일을 지정해야 합니다.
- 링크를 눌렀을 때 실제로 어떤 화면이 보이는지, 주소가 언제 바뀌는지는 3번("링크 제공")에서
  다룹니다.
- **폴더의 링크 공유를 끄면(제한됨으로 전환)** → 그 폴더 자체뿐 아니라, 그 폴더 하위에서
  **개별적으로** 링크 공유를 켜 둔 파일/폴더까지 전부 함께 꺼집니다. "상위 폴더만 잠그고
  하위의 개별 링크는 살아있는" 상태가 되지 않도록, 하위 트리 전체를 훑어서 정리합니다.
- **조상 폴더 중 하나라도 링크 공유 중인데, 그 안의 파일 하나만 제한됨으로 바꾸려 하면**
  → "상위 폴더의 액세스 권한을 삭제하시겠습니까?" 경고 모달이 뜨고, 그 파일 하나만
  조용히 바뀌는 게 아니라 **링크 공유로 되어 있는 조상 폴더 전부(그 밑의 모든 파일·폴더
  포함)의 액세스 범위가 함께 제한됨으로 바뀝니다.** 조상이 한 단계가 아니라 여러
  단계여도 마찬가지로, 그중 링크 공유인 조상은 전부 대상입니다.
  - 예시 상황:
    ```
    조부모 폴더 G    (링크 공유)
    └ 부모 폴더 P    (링크 공유)
      └ 파일 F       (제한됨으로 변경 시도) → 경고 모달 → 확인 시 G, P, F 모두 "제한됨"
    ```
  - 이유: 폴더 링크 공유는 폴더 단위로만 켜고 끌 수 있고, 그 안의 파일은 개별적으로
    링크 접근을 차단할 방법이 없습니다(위 1번의 상속 규칙과 같은 이유). 조상 중 단 하나
    라도 여전히 링크 공유 상태로 남아 있으면, 그 폴더의 링크를 가진 사람은 여전히 F까지
    들어올 수 있어서 F만 "제한됨"으로 바꿔봤자 사실상 아무것도 막히지 않기 때문에,
    "실제로 막으려면 링크 공유 중인 조상 전부를 꺼야 한다"는 걸 모달로 알리고 그 조상들과
    각각의 하위 전체를 함께 제한됨으로 바꿉니다.
- **"링크 공유(누구나 접근)"를 끄거나 켜도, 이메일로 콕 집어 보낸 초대(1번의 "직접
  공유")는 전혀 영향받지 않습니다.** 이 둘은 서로 다른 설정입니다: 링크 공유는 "이 링크를
  가진 사람이면 누구나"이고, 이메일 초대는 "이 사람 한 명"입니다. 초대받은 사람이 아직
  가입 전이라 메일로 받은 초대 링크로만 접근할 수 있는 상태였다면, 파일의 링크 공유
  설정이 어떻게 바뀌든 그 초대 링크는 계속 유효해야 하고, 이미 가입해서 정식 공유를 받은
  사람도 마찬가지로 계속 접근할 수 있어야 합니다. 그 초대를 없애고 싶다면 링크 공유
  토글이 아니라 5번의 "공유 권한 삭제"로 그 사람 것만 직접 해제해야 합니다.

## 3. 링크 제공

파일/폴더의 링크(주소)를 실제로 눌렀을 때 무엇이 보이는지는, 그 파일의 액세스 범위(2번)와
누른 사람이 로그인했는지·실제 권한을 갖고 있는지의 조합으로 정해집니다.

| 액세스 범위 | 방문자 | 결과 |
|---|---|---|
| 제한됨 | 비로그인 | 로그인 페이지로 이동 |
| 제한됨 | 로그인 + 권한 없음 | 접근 거부 |
| 제한됨 | 로그인 + 직접/상속 공유 있음 | 평소 쓰는 화면으로 바로 진입(자기 권한 그대로) |
| 링크 공유 | 비로그인 | 그대로 보여줌(뷰어 화면) |
| 링크 공유 | 로그인 (권한 있든 없든) | 그대로 보여줌(권한 있으면 자기 권한, 없으면 뷰어) |

### 처리 방식

- **로그인한 사람이 링크와 상관없이 이미 그 파일에 대한 실제 접근 권한**(소유자, 또는
  직접/상속 공유)을 갖고 있다면, 보기·다운로드만 되는 링크 전용 화면이 아니라 평소 쓰는
  전체 화면으로 바로 연결되어 자기 원래 권한(편집자일 수도 있음)을 그대로 씁니다. 이건
  "링크라서"가 아니라 "어차피 원래도 접근 권한이 있어서"입니다.
- **링크 공유 상태에서 처음 보는 비로그인 방문자**는 보기·다운로드만 되는 별도 화면(공유
  버튼도 편집 버튼도 없음)을 보게 됩니다.
- **파일 하나의 링크 주소는 액세스 범위나 방문자 종류와 무관하게 항상 하나입니다**
  (`/files/{fileId}`). 링크 공유를 껐다 켜도, 초대받은 사람이 나중에 가입해도 주소 자체는
  바뀌지 않고, 실제로 보여줄지 말지는 매번 위 표대로 다시 판정합니다. `fileId` 자체가
  이미 추측 불가능한 값이라 별도 토큰을 주소에 실을 필요가 없고, 예전에 쓰던
  `/public/{fileId}?key=...` 형태의 링크도 이 주소로 그대로 리다이렉트됩니다.
- **미가입 초대 링크**는 이 표의 "링크 공유"와는 다른, 그 사람 한 명 전용 캡슐(`?key=` 토큰)로
  동작합니다 — 파일의 액세스 범위가 무엇이든 초대받은 그 사람은 항상 들어올 수 있어야
  합니다(2번의 "이메일 초대는 링크 공유 설정과 무관" 규칙 참고). 가입 후 로그인하면
  위 표의 "직접/상속 공유 있음" 경로로 자연히 흡수되어 토큰 자체가 더는 필요 없어집니다.

## 4. 공유 권한 수정

공유해 둔 사람의 권한(뷰어 ↔ 편집자)을 나중에 바꾸는 기능입니다. **"제한됨" 범위로
공유했을 때만 해당하고, "링크 공유" 상태에는 적용되지 않습니다** — 링크는 뷰어 권한으로
고정이라 여기서 바꿀 대상 자체가 없고, 바꾸려면 2번(액세스 범위 지정)에서 다루는 방식을
써야 합니다.

### 처리 방식

- **소유자만** 수정할 수 있습니다.
- **상속 공유(상위 폴더에서 물려받아 보이는 항목)의 역할을 이 화면에서 고르면, 기존
  상속 원본을 고치는 게 아니라 이 파일에 대한 새 직접 공유가 만들어집니다.** 화면에는
  "OO 폴더에서 상속됨"이라고 표시되지만, 그 사람이 실제 가입된 멤버라면 여기서도 역할을
  바로 고를 수 있고, 고르는 순간 1번 규칙("직접 공유가 항상 이긴다")에 따라 방금 만든
  직접 공유가 상속 원본을 즉시 덮어씁니다. 상위 폴더의 원본 공유 자체는 지워지지 않고
  그대로 남아 있습니다(다른 하위 항목에는 계속 그대로 적용됨).
  - 상속된 항목이 **아직 가입하지 않은 게스트 초대**여도 마찬가지로 여기서 역할을 바로
    고를 수 있어야 합니다 — 가입된 멤버와 다르게 취급할 이유가 없습니다. 다만 로그인 없이
    쓸 수 있는 새 게스트 링크가 이 파일에 하나 더 생기는 것이므로, 일반 신규 초대 때와
    동일하게 "이 초대 링크는 로그인 없이도 접근 가능하다"는 안내를 보여주고 확인을 받은
    뒤 만들어야 합니다.

  > ⚠️ **현재 코드와의 차이 (미반영 상태)**: 지금 WEB 구현(`member-access-list.tsx`)은
  > 미가입 게스트의 상속 공유를 여기서 아예 읽기 전용으로 잠가두고, 바꾸려면 원본 상위
  > 폴더로 가게 합니다. 위 규칙(안내 확인 후 여기서도 바로 만들 수 있어야 함)이 목표
  > 방향이고, 아직 반영되지 않았습니다.

## 5. 공유 권한 삭제

공유해 둔 사람을 목록에서 완전히 제외하는(접근을 끊는) 기능입니다. **"제한됨" 범위로
공유했을 때만 해당하고, "링크 공유" 상태에는 적용되지 않습니다** — 링크는 특정 사람을
목록에서 제외하는 방식이 아니라 링크 자체를 끄는 방식이라, 링크를 끊으려면 2번(액세스
범위 지정)에서 다루는 방식을 써야 합니다.

### 처리 방식

- **소유자만** 삭제(해제)할 수 있습니다.
- **화면에는 사람 한 명당 행이 하나만 뜨고, 그 행에 삭제 버튼이 있습니다**
  (예외: 4번과 동일하게 미가입 게스트의 상속 항목은 읽기 전용). 삭제 시 동작은 2번의
  액세스 범위 변경과 동일한 패턴입니다 — **이 사람에게 조상 폴더의 공유가 남아 있으면**
  경고 모달을 띄우고, 확인 시 **이 사람의** 조상 공유들만 함께 삭제됩니다. 조상 폴더
  하위에 다른 파일에 대한 직접 공유가 존재한다면, 그건 각자 독립된 행이라 전혀
  영향받지 않습니다. 삭제할 대상이 이 사람 하나뿐이면 경고 없이 그 행 하나만 바로
  지워집니다.
  - 예시 상황:
    ```
    조부모 폴더 G    (A씨: 편집자)
    └ 부모 폴더 P    (A씨: 뷰어)
      └ 파일 F       (A씨: 편집자, 직접 공유)

    F에서 A씨 삭제 시도 → 경고 모달 → 확인 시 F, P, G의 A씨 공유 모두 삭제
    ```
